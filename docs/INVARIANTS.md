# GenLayer Fee Distribution Invariants

This document defines the 24 foundational invariants used to verify the GenLayer protocol's fee distribution mechanism. These rules represent the mathematical, economic, and strategic bedrock of the system, ensuring its correctness, fairness, and resilience against manipulation. Each invariant is checked against every possible transaction path generated by the simulator.

---

## Category A: Financial Integrity & Safety Invariants

*These invariants ensure the system is a closed, self-consistent financial loop where value is accounted for precisely and participants are protected from insolvency.*

### 1. Conservation of Value
**Statement:** The total value paid into the system by the transaction sender must equal the sum of all value distributed as earnings, all value destroyed through burns, and all value returned to the sender as a refund.
**Importance:** This is the master rule of the system's financial integrity. It proves that no value is created or destroyed from thin air, guaranteeing the system is a closed loop.
**Mathematical Formulation:**
```
Let S_cost be the total cost paid by the Sender.
Let E_total be the sum of all `earned` fields for all participants.
Let B_total be the sum of all `burned` fields for all participants.
Let R_sender be the final refund to the sender.

Invariant: S_cost == E_total + B_total + R_sender
```

### 2. Appeal Bond Coverage
**Statement:** The bond posted by an appellant must be sufficient to cover the costs of the appeal round.
**Importance:** Ensures that the appeal bond is large enough to compensate validators for their participation in the appeal round, preventing underfunded appeals that could disrupt the consensus process.
**Mathematical Formulation:**
```
For each appeal round i:
  Let bond = actual bond paid by appellant
  Let round_cost = round_size * validator_timeout + leader_timeout
  Invariant: bond >= round_cost
```

### 3. Burn Non-Negativity
**Statement:** Any amount designated as `burned` must be greater than or equal to zero.
**Importance:** A negative burn would be equivalent to creating money. This ensures the "burn" mechanism only ever removes value from the system.
**Mathematical Formulation:**
```
For each FeeEvent `e`: e.burned >= 0
```

### 4. Refund Non-Negativity
**Statement:** The final refund issued to the transaction sender must be greater than or equal to zero.
**Importance:** Guarantees a user can never be charged more than the maximum potential cost, providing them with predictable transaction costs.
**Mathematical Formulation:**
```
Let R_sender be the final refund to the sender.
Invariant: R_sender >= 0
```

### 5. Resource Pool Integrity
**Statement:** The total number of unique validator addresses participating in a transaction must not exceed the globally defined maximum.
**Importance:** A hard check on the validator allocation algorithm, ensuring it respects the fundamental resource limits of the network.
**Mathematical Formulation:**
```
Let U_addr be the set of unique addresses in the transaction.
Let M_addr be the maximum number of addresses allowed.
Invariant: len(U_addr) <= M_addr
```

### 6. Appeal Bond Consistency
**Statement:** The bond paid by an appellant must exactly match the required bond amount for that specific type of appeal.
**Importance:** Ensures that the economic cost of initiating a dispute is applied consistently and fairly.
**Mathematical Formulation:**
```
For each FeeEvent `e` where e.role == "APPEALANT":
  Let required_bond = get_required_bond(e.round_label)
  Invariant: e.cost == required_bond
```

## Category B: Protocol State & Rules Invariants

*These invariants ensure the protocol's specific state machine logic is followed without deviation.*

### 7. Sequential Processing
**Statement:** Fee events must be generated in a strictly increasing sequence.
**Importance:** Ensures the event log is ordered and can be processed deterministically.
**Mathematical Formulation:**
```
For each FeeEvent `e_i` at index `i`: e_i.sequence_id == i + 1
```

### 8. Temporal Event Consistency
**Statement:** The round index of a fee event must be less than or equal to the round index of any subsequent fee event.
**Importance:** A fine-grained check on causality, ensuring the event log correctly reflects the chronological progression of rounds.
**Mathematical Formulation:**
```
For each pair of FeeEvents e_i, e_j where i < j: e_i.round_index <= e_j.round_index
```

### 9. Appeal Logic Consistency
**Statement:** An appeal round can only occur immediately following a normal round or as part of a valid, chained sequence of appeals.
**Importance:** Enforces the structural logic of the dispute process, preventing out-of-order or nonsensical appeal scenarios.
**Mathematical Formulation:**
```
For each RoundLabel `L_i` at index `i`:
  If is_appeal(L_i): Invariant: is_normal(L_{i-1}) OR is_appeal(L_{i-1})
```

### 10. Round Size Consistency
**Statement:** The number of participants in each round must strictly adhere to the sizes defined in the protocol's constants.
**Importance:** Verifies that the critical validator selection and round-sizing algorithms are working correctly.
**Mathematical Formulation:**
```
For each Round `R_i`:
  Let N_participants = len(participants_in(R_i))
  If is_normal(R_i): Invariant: N_participants is in NORMAL_ROUND_SIZES
  Else if is_appeal(R_i): Invariant: N_participants is in APPEAL_ROUND_SIZES
```

### 11. Round Label Validity
**Statement:** Every round in a transaction must be assigned a label from the predefined, valid set of round types.
**Importance:** Ensures the protocol's logic never enters an unknown or undefined state.
**Mathematical Formulation:**
```
For each RoundLabel `L`: L is a member of the RoundLabel Enum
```

### 12. Vote Consistency
**Statement:** The vote recorded for a participant in a fee event must exactly match their vote recorded in the transaction's raw results.
**Importance:** A critical data integrity check that ensures the fee distribution logic is operating on the correct data.
**Mathematical Formulation:**
```
For each FeeEvent `e` with a vote:
  e.vote == transaction_results.rounds[e.round_index].votes[e.address]
```

### 13. Irreversibility of Finality
**Statement:** Once a transaction path reaches the `END` state, no further fee events related to that transaction can be generated.
**Importance:** Guarantees that a finalized transaction is truly final, a cornerstone of blockchain immutability.
**Mathematical Formulation:**
```
Let end_round_index = index of the "END" state.
For each FeeEvent `e`: e.round_index < end_round_index
```

## Category C: Participant Safety & Fairness Invariants

*These invariants ensure that participants are treated fairly, protected from bugs, and not exposed to undue risk.*

### 14. No Double Penalties
**Statement:** A participant cannot be penalized (burned) more than once within the same round.
**Importance:** A fundamental principle of justice preventing a single offense from triggering multiple, disproportionate penalties.
**Mathematical Formulation:**
```
For each Round `R_i`:
  Let B_addr be the set of addresses with `burned > 0` in this round.
  Invariant: len(B_addr) == len(unique(B_addr))
```

### 15. Bounded Slashing Impact
**Statement:** A participant can only be slashed once per transaction.
**Importance:** A critical safety firewall for stakers, making node operation economically predictable by strictly limiting the maximum potential loss from slashing within a single transaction.
**Mathematical Formulation:**
```
Let S_events be all FeeEvents where `slashed > 0`.
Let S_addr be the list of addresses from S_events.
Invariant: len(S_addr) == len(unique(S_addr))
```

### 16. Appellant Consistency
**Statement:** In a transaction with `N` appeals defined in the budget, there are exactly `N` appellants who incur a bond cost.
**Importance:** Ensures accounting integrity in complex, multi-appeal chains, preventing errors like misattributing or double-charging appeal bonds.
**Mathematical Formulation:**
```
Let N_appeals = transaction_budget.appealRounds
Let A_events = list of FeeEvents where e.role == "APPEALANT"
Invariant: len(A_events) == N_appeals
```

### 17. Majority/Minority Consistency
**Statement:** In an ordinary round with a clear majority decision, only validators who voted with the majority receive earnings. A successful validator appeal is the explicit exception: its own committee is settled from its own vote, and each original-round voter matching a clear new majority receives one additional validator reward. No-majority appeals do not create vindication rewards.
**Importance:** Preserves ordinary majority settlement while enforcing the retroactive incentive for correct dissent revealed by a successful appeal.
**Mathematical Formulation:**
```
For each Round `R_i` with a majority outcome `M`:
  For each FeeEvent `e` in that round where e.role == "VALIDATOR":
    If e.earned > 0: Invariant: e.vote == M

For each successful validator appeal `A` with clear majority `M_A`:
  Appeal validators voting `M_A` earn `validatorsTimeout`.
  Appeal validators not voting `M_A` incur the normal minority burn.
  Original-round validators voting `M_A` earn one `validatorsTimeout`.
  All other original-round validators earn zero and incur no retroactive burn.

For each successful validator appeal `A` with no majority:
  Appeal validators follow the existing no-majority settlement.
  Original-round validators receive no vindication reward.
```

### 18. Leader Timeout Earning
**Statement:** In a round where the leader fails to submit a result (`LEADER_TIMEOUT`), the leader's earnings for that round must be zero.
**Importance:** Ensures that non-performant leaders are not rewarded, directly incentivizing liveness.
**Mathematical Formulation:**
```
For each Round `R_i` with label "LEADER_TIMEOUT":
  Let leader_address be the leader in R_i.
  For each FeeEvent `e` in that round where e.address == leader_address:
    Invariant: e.earned == 0
```

## Category D: Economic Stability & Anti-Manipulation Invariants

*These invariants prove the protocol is not just mechanically correct, but also strategically sound and resistant to economic attacks.*

### 19. No Profit from Griefing
**Statement:** A coalition of validators who consistently vote with the minority should not be able to make a collective net profit.
**Importance:** The ultimate anti-griefing rule. It proves that sustained, malicious behavior is not a profitable strategy.
**Mathematical Formulation:**
```
Let G_coalition be the set of addresses where (minority_votes > majority_votes).
Let Profit(v) = v.earned - v.cost - v.burned - v.slashed for validator `v`.
Invariant: sum(Profit(v) for v in G_coalition) <= 0
```

### 20. Cost of Contention
**Statement:** The total economic cost of a failed appeal must be at least as large as the bond posted by the appellant.
**Importance:** Ensures that challenging the consensus has a real, tangible cost, disincentivizing frivolous appeals.
**Mathematical Formulation:**
```
For each failed appeal round `R_i`:
  Let A_cost be the appellant's bond cost.
  Let D_cost be the sum of all `burned` and `slashed` amounts for others.
  Invariant: (A_cost + D_cost) >= A_cost
```

### 21. Griefing Amplification Check
**Statement:** An appellant in a failed appeal cannot cause more damage to other participants than the value of the bond they forfeited.
**Importance:** Prevents "griefing amplification" attacks, where an attacker pays a small cost to inflict a disproportionately large amount of damage on the network.
**Mathematical Formulation:**
```
For each failed appeal round `R_i`:
  Let A_cost be the appellant's bond cost.
  Let Damage_Others be the sum of `slashed` and `burned` for all other participants.
  Invariant: Damage_Others <= A_cost
```

### 22. Progress Monotonicity (Liveness)
**Statement:** Every round must make progress by consuming a finite, non-renewable resource (addresses from the participant pool), making infinite loops impossible.
**Importance:** Guarantees transaction finality (liveness) and proves the protocol cannot be stalled by a denial-of-service attack.
**Mathematical Formulation:** This is checked algorithmically by ensuring the address allocation for each round is unique and depletes the available address pool.

### 23. Idle Slashing Correctness
**Statement:** Participants who are idle (vote `TIMEOUT`) must be slashed according to the protocol rules.
**Importance:** Enforces the core penalty mechanism that disincentivizes non-participation, ensuring network liveness.
**Mathematical Formulation:**
```
For each participant `p` where p.vote == "TIMEOUT":
  Invariant: p is slashed in the corresponding FeeEvent.
```

### 24. Deterministic Violation Slashing Correctness
**Statement:** Participants who commit a deterministic violation (e.g., double-voting) must be slashed.
**Importance:** Enforces the penalty mechanism for explicit malicious behavior, ensuring network security.
**Mathematical Formulation:**
```
For each participant `p` who commits a deterministic violation:
  Invariant: p is slashed in the corresponding FeeEvent.
```
