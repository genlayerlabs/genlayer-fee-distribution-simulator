# N-B02 appeal fee attribution

`core/attribution.py` is an independent funding ledger on top of the existing
round fee simulator. The round engine supplies completed jury and vindication
`FeeEvent`s, as well as the appellant payout. Attribution records an immutable
fee reservation at each appeal admission. Its ID, generation, and odd book
round stay attached to earned work after a void or recomputation; reuse of the
book round creates a new ID. Bond principal is recorded for context but does
not become a fee-side cost.

Jury work uses the committee's actual credited `FeeEvent.earned` values, not
its quoted seat count. A zero-earned nonaligned seat adds no fee wage. On a
failed appeal, the committee payout also contains forfeited bond principal;
the ledger subtracts that principal before assigning fee-funded jury wages.
The separate successful-appellant payout is split into returned principal and
profit, and only the profit is a fee-side charge.

Ordinary funding has separate primary and overlay columns; each is consumed
FIFO across ordinary lots and then rescue lots. A beyond-quota appellant pays
actual jury and replacement work and, on success, the appellant's profit. An
in-quota appellant pays only replacement work above the prepaid scheduled
base; the prepaid part automatically consumes ordinary primary funding. Jury
work already in the sender's quota uses ordinary primary funding. Vindication
uses the funding source that owned the original work: ordinary funding for an
original sender-funded round, or the earlier immutable admission for a prior
appeal-funded replacement. A charge first consumes its typed reservation; an
overrun consumes ordinary primary funding, without borrowing from a different
typed component. Unused balances return to their original payers.

The input contains **one** authoritative actual developer plus DAO routed
overlay. The ledger aggregates taxable work by immutable admission ID, then
derives each admission's share in admission order using cumulative integer
rounding. Event order and chunking cannot change ownership. It caps that share at the admission's
overlay reserve, and charges the residual to ordinary overlay FIFO. The global
route cannot exceed the protocol gross-up
`floor(taxableWork * combinedBps / (10000 - combinedBps))`. Failed routes can
therefore debit zero even when an overlay was reserved.

The unit boundary is intentional. The existing simulator models consensus
time-unit work. An explicit `executionBacking` event may be supplied as an
opaque amount; the model cannot infer receipt execution, storage, or custody
costs. The ownership vectors therefore do not claim to predict those costs.
They also leave the existing bond quotes and participant payout totals alone.
Most wage evidence is generated by the round engine. Replacement duty,
prior-admission vindication, and tiny rounding cases use clearly marked
`FeeEvent` fixtures because the round engine does not produce those transitions
with separate funding ownership. Consensus integration tests cover the actual
contract transitions.

Run `python3 scripts/07_generate_consensus_vectors.py --attribution-only
--output-dir <directory>` to generate the separate
`appeal_attribution_ownership.json` corpus. Each case includes observed round
fee evidence, typed admissions, chronological primary charges, one global
actual overlay route, and expected per-payer consumed and refunded amounts.
`--max-length 8 --seed 0
--existing-dir <existing simulator_results>` remains the full legacy corpus
regeneration command and emits this separate file alongside its old files.
